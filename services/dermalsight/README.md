# DermalSight service

**Status: runnable API and ONNX adapter implemented; production inference is blocked until an approved, validated model artifact is supplied.**

DermalSight owns non-diagnostic cosmetic skin-attribute inference. It is a separate service, not a placeholder hidden inside Virtual Twin. The endpoint deliberately fails closed when model assets are absent or invalid; it never substitutes heuristic output for trained-model inference.

## Runtime contract

- GET /health is liveness only.
- GET /ready returns 503 unless a model can be loaded and DERMALSIGHT_API_TOKEN is configured.
- GET /capabilities reports actual model-inference availability.
- POST /api/v1/analyze requires bearer authentication, explicit consent=true, and a JPEG, PNG or WebP image.
- Images are decoded in memory only, with byte and pixel limits, and are not persisted by this service. Deploy behind a TLS-terminating trusted ingress and configure request-body limits there as well.
- Scores are not calibrated probabilities, diagnoses, or clinical advice. The service does not infer or collect demographic identity, and it does not prescribe treatments or products.

## Model artifact requirements

Mount a model approved for **cosmetic, non-diagnostic attributes only** in secure deployment storage. Supply DERMALSIGHT_MODEL_PATH and DERMALSIGHT_MODEL_MANIFEST_PATH; do not commit model weights or secrets into Git. The manifest binds a model version and its preprocessing/output contract to the exact ONNX artifact with SHA-256. The adapter accepts only version-1 manifests for cosmetic_skin_attributes, NCHW RGB inputs, and named sigmoid attribute outputs. The ONNX runtime must expose the declared tensors. The service will not become ready if any of these checks fail.

The current repository does **not** contain a trained model artifact, validated attribute taxonomy, calibration results, or representative evaluation dataset. A fake session in unit tests validates the adapter contract only; it is not evidence of model accuracy or real inference. Before external launch, obtain rights for a chosen model, evaluate it over different skin tones, lighting, devices and capture conditions, document failure rates and subgroup performance, and have the intended claims and consent/privacy handling reviewed. The API is not production-ready for users until those gates pass.

## Configure and run

Install dependencies with: python -m pip install -r requirements.txt

Set DERMALSIGHT_API_TOKEN to a high-entropy secret generated by a secure secrets manager. Set DERMALSIGHT_MODEL_PATH to the approved ONNX artifact and DERMALSIGHT_MODEL_MANIFEST_PATH to its manifest. Then start with: uvicorn app.main:app --host 0.0.0.0 --port 8000

The manifest format is documented in app/model_adapter.py and must contain the actual artifact SHA-256 digest. The service requires Python 3.12 in the supplied Dockerfile. Do not expose it directly to the public internet without TLS, rate limiting, authentication, a secrets manager, monitoring and a privacy review.

## Tests

From this directory, install dependencies and run pytest -q. Tests cover the API security/consent boundary, image validation, fail-closed availability, manifest validation, artifact integrity, preprocessing and output-contract errors. The model adapter tests use a deterministic fake ONNX session; run an additional test suite against the actual approved model artifact before deployment.
